# TG Lead Radar

Личный радар в Telegram с двумя режимами:

- **заказы** — слушает выбранные каналы и бизнес-чаты, отбирает фриланс-заказы
  по ключевым словам и присылает в «Сохранённые сообщения» карточку: источник,
  ссылка, текст заказа и **готовый черновик отклика** под тип задачи. Остаётся
  поправить первую строку и отправить руками;
- **вакансии QA** ([режим jobs](#режим-вакансий-jobs)) — читает каналы из папки
  Telegram и выгружает вакансии сырыми данными: полный текст, извлечённые поля,
  все источники. Оценивает их внешний агент, радар не судит и не пишет отклики.

Радар **ничего не пишет в чаты** — только читает и уведомляет владельца.
Автоматическая отправка откликов не предусмотрена сознательно: это путь к бану
аккаунта и репутации спамера.

## Как это работает

```
каналы/чаты ──> Telethon (юзербот) или t.me/s (веб-режим, без ключей)
                    │  фильтр: категории (fix/bot/ai/automation/python)
                    │  анти-фильтр: реклама, чужой самопиар, штатные вакансии,
                    │               фронтенд и прочие непрофильные темы
                    │  дедупликация: SQLite, переживает рестарты
                    │  черновик: шаблон по теме или локальная модель (Ollama)
                    ▼
      карточка: время, бюджет, оценка «под профиль», текст, черновик отклика
```

## Запуск

1. Получите `api_id` / `api_hash` на https://my.telegram.org (API development
   tools, платформа Desktop).
2. `cp .env.example .env` и впишите ключи. Список каналов — там же.
3. Установка и старт:

```bash
pip install -e ".[dev]"
python -m tg_lead_radar
```

Первый вход — отдельной командой; Telegram пришлёт код подтверждения:

```bash
.venv/Scripts/python scripts/login.py
```

Скрипт сохранит сессию в `data/` и покажет, какие из каналов и чатов аккаунт
реально видит. Дальше радар запускается без вопросов.

Чтобы радар видел приватные чаты, аккаунт должен в них состоять.

Сессию нельзя делить: пока радар запущен, файл `data/radar.session` занят, и
сторонний скрипт с той же сессией получит `database is locked`. Поэтому оба
режима работают в одном процессе на одной сессии, а `discover_channels.py`
ходит через свою, отдельную сессию (см. ниже). Прочие разовые скрипты от
вашего аккаунта запускайте при остановленном радаре.

Режимы включаются в `.env` и работают одновременно:

```ini
ORDERS_ENABLED=true   # заказы (как раньше)
JOBS_ENABLED=true     # вакансии QA
```

## Режим вакансий (jobs)

```
папка «Вакансии» + JOBS_CHANNELS ──> Telethon (та же сессия, тот же процесс)
        │  первый раз: история за JOBS_BACKFILL_DAYS, дальше — только новые посты
        │  фильтр: QA-стемы; анти: реклама, курсы, менторство, резюме, разовые заказы
        │  поля: зарплата, формат, город, грейд, стек, контакты, ссылки на отклик
        │  репост ссылкой → подтягивается оригинал; форвард → записан источник
        │  дедуп: хэш текста + сходство шинглов; все источники вакансии хранятся
        ▼
data/jobs.db ──> export ──> vacancies.jsonl + YYYY-MM-DD.md
```

**Источник каналов** — папка Telegram с именем из `JOBS_FOLDER` (эмодзи в
названии не мешают). Берутся чаты, добавленные в папку руками; папка
перечитывается раз в час, так что новый канал в ней подхватится без
перезапуска. `JOBS_CHANNELS` добавляется к папке, а если папки нет — остаётся
единственным источником.

**Локальная модель в этом режиме не используется.** Задача радара — полная и
чистая выгрузка:

- полный текст поста без обрезки, с переносами строк; скрытые ссылки раскрыты
  прямо в тексте: `Откликнуться (https://hh.ru/vacancy/…)`; URL из кнопок под
  постом и из превью ссылки — в `links`;
- поля извлекаются регулярками и словарями, **при сомнении — `null`, а не
  догадка**:
  - `salary_from`, `salary_to`, `currency`, `salary_period` — «от 200к»,
    «200 000 – 300 000 ₽», «$3000», «до 250 на руки», «150-200 тыс gross»,
    «2000 ₽/час». Сумма без валюты считается рублями, только если в посте
    вообще не названа другая валюта (`default_currency` в `jobs.toml`);
    число без валюты и «к/тыс» берётся только из строки про зарплату, так что
    «опыт от 3 лет» и «компенсация фитнеса» зарплатой не станут;
  - `format` — `remote` / `hybrid` / `office`; «офис или удалёнка» → `null`;
  - `city` — один город из словаря (несколько → `null`; «по Москве» в строке
    про часовой пояс не считается);
  - `grade` — список (`["middle", "senior"]`), только из заголовка, хэштегов и
    строк вида «Грейд:»;
  - `stack` — пересечение со словарём технологий;
  - `contacts` — @username, email, t.me/<человек>, скрытые упоминания
    (`tg://user?id=…`); хэндлы каналов-источников и строки «подписывайтесь
    на @…» отброшены. Юзернеймы не резолвятся через API, поэтому изредка
    сюда может попасть чужой канал;
  - `apply_urls` — hh.ru и другие площадки, ATS, формы, career-страницы;
- репост: у форварда записан исходный канал и пост; короткий пост со ссылкой на
  один чужой пост («Новая вакансия: t.me/…/123») подтягивает оригинал — он
  попадает в `original.text`, и поля извлекаются из него;
- вложения: тип, имя файла, mime и размер — без скачивания.

**Дедупликация.** Одна вакансия обходит несколько каналов с разными шапками,
хэштегами и подписями. Дубль — это совпадение хэша нормализованного текста
или сходство 3-словных шинглов ≥ 0.8 (≥ 0.5 при совпадающем названии) за
последние 30 дней. Разные грейды или зарплаты склейку запрещают. У вакансии
хранятся все источники, основной — самый ранний пост в отслеживаемом канале;
дубль может дозаполнить поля, которых не было у первой копии.

### Выгрузка

```bash
python -m tg_lead_radar.jobs export            # всё
python -m tg_lead_radar.jobs export --since    # новое и обновлённое с прошлого --since
```

Команда читает только `data/jobs.db` и в Telegram не ходит, поэтому её можно
запускать при работающем радаре. Отметку `--since` двигает только запуск с
`--since` (хранится в SQLite), так что ручная полная выгрузка не «съест»
новое для агента. Обновлённой считается вакансия, у которой появился новый
источник или дозаполнилось поле. Файлы заменяются атомарно — читатель никогда
не увидит половину файла.

В `JOBS_EXPORT_DIR` (по умолчанию `data/jobs`, можно направить в свою папку)
появляются два вида файлов.

**`vacancies.jsonl`** — по строке на вакансию:

```json
{"id": "3f9c1a…", "posted_at": "2026-10-15T14:03:00+03:00", "channel": "qa_jobs",
 "channel_title": "QA Jobs", "message_link": "https://t.me/qa_jobs/123", "views": 1520,
 "text": "QA Automation Engineer (Middle+)\n…",
 "salary_from": 250000, "salary_to": 320000, "currency": "RUB", "salary_period": null,
 "format": "remote", "city": null, "grade": ["middle"], "stack": ["python", "pytest"],
 "contacts": ["@hr_anna"], "apply_urls": ["https://hh.ru/vacancy/1"],
 "links": ["https://hh.ru/vacancy/1"], "attachments": [], "original": null,
 "sources": [{"kind": "post", "channel": "qa_jobs", "channel_title": "QA Jobs",
              "message_link": "https://t.me/qa_jobs/123",
              "posted_at": "2026-10-15T14:03:00+03:00", "views": 1520}],
 "matched_stems": ["qa", "pytest"], "first_seen_at": "…", "updated_at": "…"}
```

`matched_stems` — какие стемы фильтра сработали (для отладки фильтра). Время —
московское, со смещением.

**`YYYY-MM-DD.md`** — дайджест за день публикации: канал, дата, ссылка, другие
каналы с той же вакансией, поля и полный текст. Радар обновляет дайджесты сам
после каждого цикла, где что-то нашлось; `export` пересобирает их тоже.

Карточки в «Сохранённые» в этом режиме по умолчанию выключены
(`JOBS_NOTIFY=false`). Если включить — придут только новые вакансии, без
истории первого запуска и без дублей.

## Поиск новых каналов: discover_channels.py

Скрипт ищет живые каналы с вакансиями QA, на которые вы ещё не подписаны, и
пишет отчёт. **Никаких подписок и вступлений** — подписываетесь вы сами.

- кандидаты: глобальный поиск по запросам из `jobs.toml` и «похожие каналы»
  Telegram для каждого канала папки; каналы и чаты, где вы уже состоите,
  исключаются;
- по каждому кандидату — последние 100 постов и число подписчиков: дней с
  последнего поста, постов за 7 дней, средние просмотры и просмотры на
  подписчика, доля QA-вакансий (тот же фильтр, что в режиме jobs), доля
  рекламы и репостов;
- итоговый скор 0–100 и пометка: **живой** (последний пост ≤ 3 дней, ≥ 3 постов
  в неделю, доля QA ≥ 10%), **мертвяк** (нет постов 30 дней), остальное —
  **сомнительный**. Пороги и веса — в `jobs.toml`;
- отчёт: `channels_report.md` и `.csv` в `JOBS_EXPORT_DIR`, по убыванию скора,
  со ссылками t.me;
- бережно к лимитам: пауза между запросами, не больше `max_candidates` за
  запуск, короткий FloodWait пережидается, длинный останавливает запуск с
  частичным отчётом.

Скрипт работает через **отдельную сессию** (`DISCOVER_SESSION_PATH`), поэтому
радар можно не останавливать. Войти в неё нужно один раз — в списке устройств
Telegram появится второй сеанс того же аккаунта:

```bash
python scripts/login.py --session data/discover
python scripts/discover_channels.py
```

`--session data/radar` запустит его на основной сессии — тогда радар
должен быть остановлен, иначе скрипт откажется работать.

## Автозапуск (Windows)

`scripts/run_radar.vbs` запускает радар скрыто и пишет лог в `data/radar.log`.
Достаточно положить ярлык на него в папку автозагрузки:

```powershell
$vbs = "$PWD\scripts\run_radar.vbs"
$lnk = Join-Path ([Environment]::GetFolderPath('Startup')) "TG Lead Radar.lnk"
$s = (New-Object -ComObject WScript.Shell).CreateShortcut($lnk)
$s.TargetPath = "wscript.exe"; $s.Arguments = "`"$vbs`""; $s.WorkingDirectory = "$PWD"; $s.Save()
```

Второй экземпляр запуститься не сможет: радар держит файловый замок
`data/radar.lock`, так что автозапуск и ручной запуск не задвоят уведомления.

## Локальная модель как второй контур (режим заказов, опционально)

Ключевые слова — дешёвый контур полноты: пропускают всё, что похоже на заказ.
Локальная модель — контур точности. Если рядом поднят [Ollama](https://ollama.com),
каждый прошедший пост уходит модели, и она возвращает JSON-вердикт:

- **заказ ли это** (вакансии в штат, реклама курсов, самопиар студий — отсеиваются);
- **оценку соответствия** профилю (1–3 звезды);
- **строку «при чём тут вы»** — что за задача и какие навыки нужны;
- **персональный черновик отклика** под конкретный текст заказа.

В промпте — фиксированный список фактов об исполнителе, включая то, чего он
**не** берёт (вёрстка, дизайн, фронтенд, штат). Выдумывать опыт запрещено,
сроки и цены модель не называет.

```bash
ollama pull qwen2.5:7b
# в .env:
# LLM_ENABLED=true
```

Модель работает на своём железе, тексты заказов никуда не отправляются. Если
Ollama выключен, не ответил или вернул мусор — остаётся вердикт ключевых
фильтров и шаблонный черновик, радар не останавливается.

## Настройка фильтров

Заказы: категории и стемы — в [filters.py](tg_lead_radar/filters.py) (стем
матчится по началу слова: «бот» ловит «бота/ботов», но не «работа»). Черновики
откликов — в [templates.py](tg_lead_radar/templates.py); при нескольких
категориях побеждает более специфичная (fix > bot > ai > automation > python).

Вакансии и discover: всё, что стоит подкручивать, — в [jobs.toml](jobs.toml):
QA-стемы, анти-фильтры (по всему тексту и только по заголовку), маркеры
зарплаты, словари городов, грейдов и стека, домены для ссылок на отклик,
пороги дедупликации, поисковые запросы, пороги и веса скоринга каналов. В
`[filter]` каждое слово — стем («автоматизац тестир» ловит «автоматизация
тестирования»); в словарях слово целое, а `*` в конце делает его стемом.

## Переменные .env

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ORDERS_ENABLED` | `true` | режим заказов |
| `JOBS_ENABLED` | `false` | режим вакансий QA |
| `JOBS_FOLDER` | `Вакансии` | папка Telegram с каналами вакансий |
| `JOBS_CHANNELS` | — | доп. каналы через запятую (без @) |
| `JOBS_BACKFILL_DAYS` | `14` | глубина истории при первом чтении канала |
| `JOBS_EXPORT_DIR` | `data/jobs` | куда класть jsonl, дайджесты и отчёт discover |
| `JOBS_DB_PATH` | `data/jobs.db` | база режима jobs |
| `JOBS_CONFIG_PATH` | `jobs.toml` | списки, словари и пороги |
| `JOBS_NOTIFY` | `false` | карточки новых вакансий в «Сохранённые» |
| `DISCOVER_SESSION_PATH` | `data/discover` | отдельная сессия для discover |

Остальные переменные (`API_ID`, `CHANNELS`, `LLM_ENABLED`…) — в
[.env.example](.env.example).
